# 桌面 Computer 退出、接管与部署恢复

关联：#bugfix task #4、PR #131。实现与验证：2026-10-02，Jack-mac。

## 问题与证据边界

私有部署桌面包可能沿用默认状态目录中另一部署的 Computer 会话。旧退出编排先等待服务停止再记录进程，容易漏掉已经脱离父进程的子进程；重复触发退出还会绕过未完成的清理。旧扫描把存活根的整个进程组纳入清理，同组的另一状态目录服务、桌面 GUI 和未知进程都会被波及。

已对交接版本的 `collectSurvivorPlan` 做纯函数隔离复现：一条可信根 PID 100、另一根 PID 200、GUI PID 7 同属 PGID 50，旧代码将三者全部认领；修复只认领 PID 100。另有真实临时进程回归验证修复后的信号隔离和孤儿清理。

这些证据证明代码风险及修复行为，不能证明 2026-10-02 14:32 的现用服务停止就是这条路径触发。原始日志来源保留如下，实际调用方仍待确认：

- `~/.slock-raft/computer/run/service.log`：06:32:23.465Z、06:32:23.568Z 的 runner `shutdown-stop`。
- `~/.slock/computer/run/service.log`：06:32:45 runner 启动、06:33:02 起失败与 14:34:04 Electron 崩溃痕迹。
- 生产根 owner:cli 与旧根 owner:app 的生命周期标记是取证线索，不能单独排除所有调用路径。
- `/__service` 模块错误早于桌面安装。Electron 的 Node 模式和入口参数错位能产生类似错误；未取得历史启动命令，不把候选机制写成已确认事实。

后续另两起测试污染事故由 Shrimp-mac 对账确认，属于 task #5 的测试隔离修复，不能混为本任务事故归因。

## 实现

### 统一进程归属

`ComputerProcessScope` 同时供接管门禁与退出编排使用。进程证据包括精确状态目录、PID、`lstart` 和命令。状态目录从 `RAFT_HOME`、`SLOCK_HOME`、`--slock-home` 读取；多个标记冲突、目录不可识别时默认不杀。按完整路径比较，避免 `.slock` 与 `.slock-raft` 前缀混淆；支持路径中含空格。

可信 pidfile 指向已验证的 service/runner；同根的代理标记及已验证父进程的后代可纳入清理。GUI 及其 Helpers 排除在外，不把继承的代理标记当作 GUI 归属证明。停止前固定身份，pidfile 删除或进程成为孤儿后仍保留记录；不能验证的已知后代保留为未完成项。

清理完全取消进程组信号。每个 TERM/KILL 都是正 PID，发信号前重新扫描并核对目录、启动时间和命令；身份变化或 PID 复用时不发信号。`ps` 读取失败不会伪装为全清空，原始环境内容不写入日志或 IPC。

### 退出编排

退出前记录进程，再并行请求服务正常停止并执行有界升级清理。普通退出宽限 15 秒、TERM 与 KILL 各 5 秒；系统关机使用更短期限。实际经过时间决定升级，不让等待 stop 请求阻塞清理。

重复退出统一拦截并共享正在执行的尝试；取消、异常和未完成清理会重新开放重试。只有核实清理完成才允许真正退出。无法读取身份时保持应用并提示重试。即使状态报告没有运行服务，也检查孤儿进程。

### 会话与恢复

接管、启用、启动、停止、重启、替换服务和升级先验证本地会话 origin 与构建 API origin。损坏或不可读会话阻断；只有文件不存在才按新机器处理。原会话和旧挂载不被自动删除或覆盖。已有 Computer 认证保持权威，网页账号不同则提示独立认证。

冲突时，已挂载和未挂载的计算机卡片都提供“连接当前部署”。确认界面展示旧部署、目标部署、旧目录和旧连接；确认后在桌面应用数据目录内创建独立 Computer 根并完成设备授权。API 与网页登录可以使用不同 origin，打开网页前明确展示目标 URL，拒绝非 HTTP(S) 与含用户名密码的地址。

认证成功且账号与当前桌面账号一致，才用临时文件加 rename 原子保存目录选择。重启恢复选定根；重复连接复用同部署、同账号的已认证目录。取消、失败或错误账号保留旧会话、旧挂载和原目录选择，删除的仅是本次新建目录。切换不会自动启动服务或迁移旧挂载，用户重新添加有权限的连接。

连接期间拒绝新的生命周期操作；已有操作未收尾时拒绝切换。退出会取消认证并等待本次连接收尾，再进入稳定根的清理流程。所有后续操作及安装器子进程显式绑定选定根的两个环境变量；手动升级备用命令也绑定该目录并进行 shell 引用。

### 子进程启动

service 与 runner 子进程显式设置相同的 `RAFT_HOME`、`SLOCK_HOME`。打包 Electron 自行加载 app，不再把 `argv[1]` 当 Node 入口文件；Electron 子进程去掉继承的 `ELECTRON_RUN_AS_NODE`。Node CLI、开发 Electron 与 SEA 原有入口形式保留。

## 验证与限制

全部测试在独立临时目录运行，显式绑定两个状态根环境变量；每次前后核对现用 `user-session.json` 摘要未变，不输出凭据。

- 桌面完整单元测试 130 项通过，运行时 29 项、更新器 2 项通过。单元测试覆盖混合进程组、两根、GUI/Helper、孤儿、PID 复用、未知身份、重复退出、超时升级及会话恢复。
- 真实进程回归创建两个临时根：另根服务与本根服务同 PGID，本根子进程脱离父进程并忽略 TERM；最终子进程清理完成，另根服务存活且 TERM 记录为空，测试驱动仍存活。
- Computer 登录/停止 23 项、纯启动参数 6 项通过，覆盖取消后零会话写入、异步身份校验失败不清 pidfile，以及打包 Electron 参数。
- 主进程与 Computer 类型检查、桌面主程序与前端构建、运行时与更新器测试完成。
- 前端独立类型检查有既有错误：jsdom 声明缺失、SettingsPanel 的计时器类型、ThreadsInbox 的 React Ref 版本类型冲突、webAppVersion 的环境类型。未修改副本 HEAD=44cbef2 复现同样五处错误，本次变更文件无新增错误。

进程识别基于 macOS `ps` 可观测信息，检查与发送信号之间存在操作系统竞态窗口；启动身份和命令复核降低 PID 复用风险，不能宣称 POSIX 信号操作具备原子身份保证。缺少明确根证据的历史进程会保留并报告，不扩大清理范围。
