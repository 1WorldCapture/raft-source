## 实现

- 登录正常用例全部显式注入浏览器回调。Vitest 环境中，`runLogin` 若缺少回调，在申请设备码前直接拒绝；检查位于可吞异常的设备码事件回调之外。普通 CLI 的默认浏览器行为保留。
- 默认 Vitest 配置在业务测试导入前安装测试专用连接与子进程守卫。直接 fetch、undici、HTTP/HTTPS 均经过 Node Socket 连接边界，真实 TCP 只允许回环地址上由本次测试注册的端口，并在连接前确认登记进程仍存活、启动身份一致；Linux 使用内核启动 ticks，macOS 使用进程状态/启动时间，Windows 分支使用进程启动 ticks，僵尸或身份不可读时拒绝连接。已关闭的模拟服务端口直接返回连接拒绝，不实际连接，避免端口被其他服务复用后误访问。纯 MockAgent 响应不创建真实连接，可以使用模拟的远端 URL。
- 守卫通过 `NODE_OPTIONS --import` 传递给 Node 子进程，显式提供子进程环境也会补齐守卫。注册端口与违规审计在临时目录共享，子进程的真实副作用不会逃过父套件核对。
- 浏览器命令及直接 shell 浏览器调用在启动前阻断。安装脚本通过 PATH 启动的 curl/wget 使用测试包装器：仅允许已注册的本机 URL 和本地文件 URL，采用下载参数白名单，拒绝额外裸地址、其他协议、代理/目标覆盖与重定向。Node 直接调用 curl/wget（含绝对路径）也被转入同一包装器。现有本地安装器模拟下载可继续运行。
- 每条拒绝记录保留副作用类型、目标主机/端口、PID 和用例名，不记录令牌、设备码或请求正文。每个用例及文件结束均检查审计，业务代码吞掉拒绝异常也会导致套件失败。
- 测试与清理默认限时两分钟，避免遗漏模拟导致无限等待。测试清单计数同步更新。

默认 `pnpm --filter @botiverse/raft-computer test` 即启用上述守卫与失败断言，可用于 CI；不依赖操作者额外设置网络隔离开关。测试专用模块不被生产入口导入。

## 技术复审修订

Anna 的独立临时进程复现发现：模拟服务被 SIGKILL 后没有 close 事件，旧登记会保持 live，允许外来服务复用端口。复修在连接前检查登记 PID 的操作系统启动身份与存活状态，身份缺失或不一致默认拒绝，不仅依赖正常 close。新增两项回归：先验证子进程模拟服务可访问，再 SIGKILL，随后由未登记服务复用端口，强制新建 TCP 连接并断言零请求；同 PID 但登记启动身份不一致也拒绝。

修订后 13 项边界、8 项 CLI 登录和 22 项本机认证定向测试全部通过（43 项，日志 `desktop-isolated-174959-673237.log`）；诊断及认证客户端追加 34 项通过（`desktop-isolated-175055-372547.log`），合计 77 项定向验证，现用会话摘要均不变。类型检查通过（`desktop-isolated-174949-077126.log`）。首版全量结果不能替代修订后的全量验证；遵循 Anna 的限制，本次先交定向回归供复审，未经她解除限制不复跑全量。GitHub 仓库当前没有为此 PR 配置 CI checks，本文的 CI 回归指默认 Vitest 的失败门槛及独立故意吞错运行验证。

## 适用范围

守卫覆盖本套件使用的 Node TCP、子进程以及 shell 原生工具路径，不替代操作系统沙箱。新增其他语言网络客户端、原生插件或新的浏览器启动方式时，应先扩展对应边界和负向回归。当前实机验证为 macOS arm64，Windows 分支需要在对应平台运行。

已知挂起的旧命令没有恢复执行。完整守卫回归通过后，在独立修复分支运行带守卫的新全量套件，并保留完整输出；历史缺失证据不能由新回归补成事故定因。
